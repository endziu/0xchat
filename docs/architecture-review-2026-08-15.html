Candidate 01

Concentrate the identity lifecycle

Files

Problem. Identity switching, login, logout, push cleanup, stale-attempt safety, and commit ordering span four modules; the root must know the transaction.

Solution. Deepen the identity lifecycle module so its implementation owns transition invariants and the root consumes outcomes, without deleting the tested transition logic.

  • locality: sequencing concentrates
  • leverage: root learns less
  • tests: one lifecycle seam

Candidate 04

Deepen the registration ceremony

Worth exploringin-process

Files

src/server/routes/register.tssrc/server/challenge.ts src/server/validation.tssrc/shared/registration-challenge.ts src/client/lib/api.tssrc/client/hooks/useIdentity.ts

Problem. Origin binding, address/public-key validation, challenge text, nonce consumption, signature verification, and recording form an implicit protocol spread across client, route, store, and validation modules.

Solution. Deepen the registration ceremony around the shared canonical artifact; keep challenge storage as implementation detail rather than exposing more transaction steps.

  • locality: protocol changes concentrate
  • leverage: canonical rules reused
  • tests: ceremony through seam

Top recommendation

Concentrate the identity lifecycle

It is the clearest shallow interface around a proven deep implementation: security-sensitive sequencing currently leaks into the root, and focused tests already show where the leverage is.
